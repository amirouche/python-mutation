## websockets — Survivors Detail

**Version**: HEAD (`released = False`)
**Tested**: 100-mutation sample (seed=42) | **Survived**: 71 (71%)

### Setup Notes
- 38,476 total mutations across 46 source files — full run estimated ~3 days at 1 worker.
- Test suite: 2158 passed, 80 skipped. Required `WEBSOCKETS_TESTS_TIMEOUT_FACTOR=10` to stabilize async timing tests. `pytest-xdist` incompatible.

### Root Cause A — Type annotation mutations (66/71 survivors, `connection.py:33`)

`Connection.__init__` uses `int | None` / `float | None` union syntax. The tool replaces `|` with arithmetic operators (`//`, `**`, `+`, `-`, `*`, `/`, `%`, `&`, `^`, `@`) and `None` with `True`/`False`. Since Python evaluates annotations lazily, these mutations are syntactically valid and semantically inert — no test catches them.

Example:
```diff
-    def __init__(self, ..., ping_interval: float | None = 20, ...):
+    def __init__(self, ..., ping_interval: float // None = 20, ...):
```

**Not actionable for a test PR** — runtime type enforcement would require `isinstance` checks or a runtime type checker. This is a known limitation of mutation testing with Python type annotations.

### Root Cause B — Import/statement drops (5 survivors, `connection.py`)

| Line | Original | Mutation | Reason survives |
|------|----------|----------|-----------------|
| 7 | `import uuid` | `pass` | No test asserts ping IDs use UUID format |
| 9 | `from types import TracebackType` | `pass` | Used only in annotations |
| 13 | `from ..http11 import Request, Response` | `pass` | Import dropped at module load; tests may re-import via other paths |
| 18 | `__all__ = ['Connection']` | `pass` | `__all__` not enforced by tests |
| 21 | docstring | `"""mutated string …` | Docstrings don't affect behavior |

**Actionable**: A test asserting that ping frame identifiers are valid UUIDs would kill the `import uuid` → `pass` mutation.

**Version**: babel (latest)
**Tested**: 3,639 mutations (10% sample, seed=42, 27 source files) | **Survived**: 2 (0.055%)

### Setup Notes

### Survivors — `babel/messages/setuptools_frontend.py` (lines 103–108)

Both survivors mutate string keys in the `COMMANDS` dict:

```python
# original
COMMANDS = {
    'compile_catalog': compile_catalog,
    'extract_messages': extract_messages,
    ...
}
```

```diff
# survivor 1 — key renamed, no test catches it
-    'compile_catalog': compile_catalog,
+    'mutated string compile_catalog': compile_catalog,

# survivor 2 — key renamed, no test catches it
-    'extract_messages': extract_messages,
+    'mutated string extract_messages': extract_messages,
```

**Why it matters**: The `COMMANDS` dict maps command names to distutils command classes. These names must match what setuptools expects. If a key is wrong, the `compile_catalog` or `extract_messages` commands would silently disappear from `setup.py`. No test verifies the dict keys exist or are correct strings.

**PR candidate**: A simple test that looks up `COMMANDS['compile_catalog']` and `COMMANDS['extract_messages']` and asserts they are the expected classes would kill both mutations.
